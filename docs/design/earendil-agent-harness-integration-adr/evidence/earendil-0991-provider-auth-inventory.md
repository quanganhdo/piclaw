Bedrock's provider-owned API-key setup offers bearer token, AWS profile and existing credential-chain choices. Vertex offers API key, Application Default Credentials and service-account-file choices. Those external routes are **source annotations**, with source paths in the inventory; no cloud identity, metadata endpoint or credential file is probed. Optional Piclaw Azure OpenAI/Foundry bootstrap routes are likewise source annotations. Custom/local providers are recorded separately: a local no-key configuration is not an invented OAuth or API-key login.

Piclaw now treats an available `getProviders()` inventory as authoritative. A provider absent from that inventory, or an inventory read failure, cannot retain a stale static OAuth/API-key login method. Static fallback remains for legacy hosts that expose no inventory API. Custom configuration forms retain their separate configuration semantics.

## Published OpenAI and Codex execution

The disposable probe imports `builtinProviders()` and invokes each provider's public OAuth method. It uses the installed package, not source-tree substitutions or private OAuth imports. The installed version must be exactly 0.99.1.

A test-owned server occupies loopback port 1455, forcing each published flow's supported pasted-redirect handoff. Synthetic callbacks preserve state and PKCE. Every fetch is replaced by an exact provider-endpoint assertion and synthetic token response; no request reaches OpenAI. Refresh checks grant type, refresh token, client ID and provider-specific resource. The cancellation case aborts a blocked synthetic token request and verifies the fetch signal was observed. Bad state rejects before token exchange.
