# Bounded local-note query

`memory_query` searches the published single-user note-chunk index and returns source-verified snippet references. This is the query slice of [#387](https://github.com/rcarmo/piclaw/issues/387), stacked on the exact-reference `memory_get` change in [PR #1425](https://github.com/rcarmo/piclaw/pull/1425). Neither change is installed on Smith.

The registered tool requires explicit activation and the same captured session/chat, access mode, execution identity, workspace and database binding as `memory_get`. It does not export an unrestricted reader or accept a path selector. A query has a 512-character input bound, 1–5 returned hits, candidate offset 0–50, at most 20 chunk validation operations including parent context and a 16 KiB serialised output ceiling. It uses bounded lexical/heading candidate streams, explicit phrase/identifier constraints and deterministic lexical/BM25 ranking before top-five packing; explicit FTS expressions retain their boolean semantics. It does not apply a no-answer rejection policy. The [ranked-context implementation](local-note-ranked-context.md) documents the fixed SQL pool and separately gettable parent-heading references. Each hit contains a bounded snippet drawn from the validated source, `{chunk_id, source_revision}`, path, heading ancestry, kind, original byte/line range, rank, index generation and validation timestamp. `memory_get` supplies the full bounded chunk for an exact reference.

The query returns `partial` with closed reasons when the scan is overdue, coverage is limited, source validation fails, a known dirty path exists, or candidate/output budgets are exhausted. A zero-hit partial response does not establish absence of an answer. Source edits, deletions and link replacements withhold affected text, dirty that path and request the existing background index coordinator. It never runs a synchronous full scan. It checks scope dirty/coverage generations, publication and source identities before returning; a changing publication or scope discards candidate text. Filesystem edits after final validation remain possible. A five-minute reconciliation eligibility target is documented in the [accepted retrieval contract](local-note-retrieval-contract.md); it is not a demonstrated delivery deadline. Cooperative read deadlines do not bound blocked network filesystem I/O.

The 20-candidate and 16 KiB caps are conservative implementation limits. They are not approved #1346 quality or performance budgets. The frozen #1422/#1423 synthetic experiments show potential trade-offs but do not establish production ranking policy. The pure context assembler merged in [PR #1424](https://github.com/rcarmo/piclaw/pull/1424) is unchanged. Parent lookup is performed separately inside the admitted tool closure and returns each parent's own original stored reference. Existing `search_workspace` behaviour is unchanged.
