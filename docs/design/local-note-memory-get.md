# Exact-reference note reads

`memory_get` resolves `{chunk_id, source_revision}` against the current published note index. It returns the verified chunk text and its citation metadata, or a status without note content. This is the `get` slice of #387; it does not implement `memory_query`, candidate selection, ranking or multi-chunk context assembly.

The tool is registered with the built-in extensions but requires explicit activation. Its server-created factory captures the chat binding. The registered `execute` closure requires a live matching session context, active tool grant and [single-user note-index admission](local-note-retrieval-contract.md). The content reader is private to that closure. A no-identity call outside that tool context cannot read indexed notes. Family-shared, isolated-container and invalid identity calls are denied before parsing selectors or opening note rows.

The reader resolves only the supplied reference in the published namespace. It validates the index binding and state, recomputes the chunk ID from the stored byte range, opens the admitted note path and hashes the complete file bytes. It compares the exact source slice, line bounds and stored content bytes. It then rechecks source identity, state markers, dirty paths, row contents, database binding, session and cancellation before returning. It does not redirect stale references to a nearby or re-ranked passage. A detected source edit, disappearance or link replacement invalidates that file and requests background reconciliation; there is no synchronous indexing in the tool call. The returned `validated_at` marks the final validation point, not a guarantee against later filesystem edits.

Responses have a finite 2-second cooperative deadline and 32 KiB serialised output ceiling. These are implementation safety limits, **not** approved #1346 ranking or deployment-performance budgets. Filesystem operations can block past a cooperative deadline. Missing or incompatible publications fail closed; cancellation and authority loss return no content.

The index writer now binds chunk and FTS content as UTF-8 bytes cast to SQLite TEXT. Bun's string binding strips an initial UTF-8 BOM; without byte-preserving storage, a stored chunk can disagree with its revision-bound byte range. The reader compares stored content as hex-encoded bytes rather than relying on SQLite's text decoding.

`memory_query` remains the separate integration step. It needs bounded candidate selection, per-hit source validation and query-wide scope/coverage freshness checks from the accepted [retrieval contract](local-note-retrieval-contract.md). The bounded context assembler is proposed separately in [PR #1424](https://github.com/rcarmo/piclaw/pull/1424). Experimental ranking and no-answer rejection in #1422/#1423 do not establish production policy; #1346 budgets still need approval. This slice neither changes the existing `search_workspace` tool nor installs or activates anything on Smith.
